# 공개 평가 세트 개정과 수집기 계약

현재 revision은 `cbt-known-scope-2`다. `known/`의 160개 단일 사례와 10개 장기 정의를 양쪽 버전에 동일하게 사용한다. `known-original/`은 과거 원본 보존용이다. 원래 Drive 파일은 덮어쓰지 않았다. `known-revision-manifest.json`의 현재 hash가 실행 잠금 대상이고 `known-input-lock.json`은 원래 신원의 증거다.

기존 expected 모순·불필요한 영역 강제·과도한 내부 gate를 교정했다. 68개 논리 사례에 변경이 있으나 40개는 공통 금지 방향의 적용 조건 명확화다. 68개 모두가 실패/무효라는 뜻이 아니다. 공개 단일 사용자 발화는 그대로이며, 장기 Q9_LONG_REHYDRATE_READY의 추상적인 영역별 고정 답변은 동일 기준 기록의 구체적 사실을 말하는 자발적 발화로 바꿨다.

## 수집기에서 필요한 변경

- expectedDecision이 문자열이면 기존 단일 기대를 읽는다. null이면서 allowedDecisions가 있으면 그 목록을 사전 허용 경로로 읽는다. 이때 expectedAssessment=null은 NO_CLEAR 또는 무응답의 기대값이 아니라 고정된 단일 class가 없다는 뜻이다. expectedDistortions의 빈 목록을 “왜곡 코드 금지”로 오해하지 않는다. assessmentPolicy가 실제 근거 판단 원칙이다.
- MULTIPLE_VALID_ACTIONS는 10개 ID로 미리 고정돼 있다. 품질100점·응답률·전체184×2 수집에는 모두 포함한다. 단일 정답 분류 진단에 섞어 정당한 다른 행동을 오답 처리하지 않는다. 해당 10개의 실제 행동 분포와 품질은 별도로 보이며 분류 진단의 대상 수 변화는 rubric v1.12대로 공개한다. 기존 진단 대상 세트와 사전 gold의 safety 여부로 N과 대상 ID를 첫 출력 전에 잠근다. 실제 안전 오경보·STOP·null·무응답 때문에 대상을 제외하지 않고 비일치로 남긴다. 한쪽 출력에 따라 적용 대상을 바꾸지 않는다.
- 원래 필드 schema에서 array expectedDecision을 받도록 임시 완화하지 않는다. 위의 nullable scalar+allowedDecisions라는 동일 규격을 양쪽 수집에 사용한다. 제품 입력은 기존 공개 요청 필드만 명시적으로 골라 만들며 모든 평가 metadata를 제외한다.
- requiredGates의 새 항목은 사용자에게 관측되는 기능의 확인 목적이다. 문자열 이름으로 새 제품 validator를 생성하지 않는다. 실제 원문·응답·복원 이력에 대한 감사 근거를 남긴다. 정답 라벨 불일치나 형식 취향 때문에 공식 case를 재실행/삭제하지 않는다. Codex는 점수를 매기지 않는다.
- 고정 장기 발화는 자발적 정보/피드백이다. 실제 parent 질문이 반복됐는지는 질문 이력으로 확인하며 항의 문장 자체를 반복 발생 증거로 쓰지 않는다. 복원·후속 단계 전에 정당한 기존 확인/중단으로 끝나면 세션 raw를 보존하고 미관측 분기를 표시한다. 복원/정해진 턴 수를 채우려고 제품을 계속 질문하게 만들지 않는다. 실제 기능 미관측과 제품 실패를 구분한다.
- 봉인14는 변경하지 않았고 키/평문도 읽지 않았다. 정식 공개 뒤 테스트 오류가 발견되면 사전 범위 정책으로 양쪽 동일하게 기록하며 실행 중 입력·expected를 바꾸거나 새 유료 retry를 만들지 않는다.

## 변경 정합성

NO_CLEAR와 비어 있지 않은 distortion 정답의 모순4건을 원래 자동사고 기준으로 바로잡았다. 현재 사용자가 더 균형 있게 답했다고 원래 생각을 새로운 판단 대상으로 교체하지 않는다. Q9H14와 Q6E04의 필수 왜곡 코드도 제공된 정의와 실제 문장에 맞게 정정했다. 상충했던 coverage 주석은 네 사례에서 null로 비활성화했고 원문 해석을 임의로 사실 인증하지 않았다. 안전 두 사례의 completionAssessmentAllowed=true 주석도 실제 SAFETY_STOP 기대와 정합화했다.

이 개정은 실행 전 테스트 품질 수정이다. 과거 평가의 동일 입력/동일 정답을 유지한 비교가 아니므로 이전 점수와 직접적인 개선율로 비교하지 않는다. 새 Q10/Q11 대응 비교는 같은 현재 revision으로 수행한다.
