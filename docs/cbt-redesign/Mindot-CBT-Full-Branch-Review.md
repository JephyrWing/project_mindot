# Mindot 전체 브랜치 리뷰 계약

이번 순서: **구현 → 원격 fix/CBTAI push → ChatGPT 전체 브랜치 리뷰 → 테스트**. 사용자가 직접 지정한 단계다. Codex의 자체 점검·diff 설명·컴파일 결과는 ChatGPT 리뷰를 대신하지 않는다.

## 1. Codex가 제출할 자료

- 저장소 `JephyrWing/project_mindot`, 작업 시작 SHA, 최종 로컬 SHA, push 후 원격 SHA. 원격과 로컬이 같다는 실제 확인 결과.
- 변경·삭제·추가 파일 목록과 목적, 현재 라우트/DTO/저장/조회/화면 흐름 지도. 작업 시작 뒤 합쳐진 팀원 변경도 구별한다.
- 최종 커밋의 전체 tracked 파일 목록과 자사 코드·설정·테스트의 bytes/SHA-256. 빌드 산출물·라이브러리 설치물·과거 artifacts/raw는 별도 분류한다. 누락한 파일과 이유를 기록한다.
- 세 앱의 전체 자사 소스, 설정, 의존성 선언, 작성한 테스트와 runner, 구현에 사용한 이번 명세·프롬프트를 담은 소스 ZIP. diff만 제공하지 않는다. 커밋에 존재하는 과거 평가 묶음을 새 실행 자료처럼 재포장하지 않는다. 전체 tracked 목록으로 해당 역사 자료도 식별할 수 있게 한다.
- 실제 실행 명령과 결과, 테스트 미실행 상태, 코드상 남은 문제·불확실성. `.env` 비밀값·토큰·운영 DB·사용자 개인정보는 ZIP에 넣지 않는다. 필요한 설정 키는 값 없는 예제로 기록한다.

소스 ZIP을 다시 만들거나 누락 파일을 보완하는 일 때문에 제품 모델을 호출하지 않는다. 원격 source가 최종 리뷰 기준이다.

## 2. ChatGPT가 읽을 범위

원격 HEAD를 SHA로 고정하고 전체 tree를 확보한다. AI의 facade/app에서 시작해 실제 활성 엔진과 호출되는 Writer/Assessor/검토/저장 코드, 기록 분석·기타 AI 경로와 남은 비활성 자사 엔진까지 읽고 실제 호출 여부를 구별한다. Spring과 React도 엔트리·라우터부터 전체 자사 코드·설정·테스트를 읽는다. 생성 코드·binary asset·lockfile·과거 raw는 용도를 분류하고 구조·의존성 메타데이터를 확인하며 자연어 또는 실행 소스와 같은 방식으로 읽었다고 주장하지 않는다.

리뷰 원장에는 경로, 읽은 SHA/hash, 용도, 호출/소비자, 확인 내용, 읽지 못한 범위를 남긴다. 단순 rg 검색 결과나 Codex 요약만으로 전체 읽기 완료 처리하지 않는다. diff는 영향을 찾는 보조 자료다. 수정하지 않은 호출처도 새로운 결과와 상태를 제대로 소비하는지 확인한다.

| 기능 연결 | 반드시 추적할 결과 |
|---|---|
| 인증·소유권·기록 생성/수정/삭제 | 다른 사용자의 기록 혼입 없음, 원래 자동사고 보존, CBT API 변경과 무관한 기존 사용 흐름 유지 |
| 첫 시작·재개·새 답변 | full hydrate와 delta 연결, 실제 assistant/user 순서, 미답변 질문 및 저장된 미승인 제안 복원 |
| 일반 질문·도움·정정 | 새 schema에 옛 ledger 요구가 숨지 않음, 혼합 답변과 부분 정정 원문이 Writer/Assessor까지 전달됨 |
| AFTER·제안·설명 | 최초 판단의 잘못 인식과 수정이 있어야 제안, 단순 동의는 재생성하지 않음, 설명 후 승인 가능 |
| 뜻 정정·변화 철회 | 이전 제안 승인 불가, 새 AFTER와 옛 라벨 혼합 없음, 바뀐 생각이 없으면 발명하지 않음 |
| 확인·유형 거부·저장 | 사용자가 본 제안과 저장 결과 일치, 모든 유형 거부 가능, 승인 전후 상태 구별 |
| 나중에 이어하기·완전 종료·안전 중단 | OPEN/CANCELLED/COMPLETED/SAFETY_STOPPED의 실제 버튼/API 연결, 취소 뒤 늦은 결과 차단 |
| 중복·timeout·재시작·메모리 유실 | 입력 선저장, 동일 턴 중복 없음, typed resync, 만료 job 복구, 유령 응답으로 다음 턴 진행 없음 |
| 기록 목록·정렬·상세·이어하기 목록 | 새/구형 결과 표시와 최신 팀원 페이지·정렬 계약 보존, CLOSED 세션 재개 금지 |
| 주간 보고서·PDF·RAG·임베딩 재시도 | 확정 AFTER와 수락 유형만 소비, 과거 라벨 차집합 오해 제거, 구형 의미 보존, 검색 대상·확신도 대상 일치 |
| 공용 DTO·enum·설정·의존성·배포 연결 | 삭제 endpoint/필드의 모든 소비자 추적, CORS/timeout 설정 일치, 의도치 않은 test/deploy hook 없음 |

새 스키마를 읽는 생산자·저장자·조회자·UI·보고서·검색을 한 행으로 연결한 표도 만든다. `afterText`, `suggestions/reviews`, `status/phase`, `revision`, `currentProposal`, `confirmedResult` 각각에 실제 파일 근거를 적는다.

## 3. 판정과 테스트 전환

- `CHANGES_REQUIRED`: 핵심 기능 유실, 계약 불일치, 잘못된 승인·저장, 복원 불능 등 코드에서 확인한 결함이 남음. 원인과 후속 영향을 고쳐 push한 뒤 최종 브랜치를 다시 확인한다.
- `REVIEW_INCOMPLETE`: 실제 소스 일부를 읽지 못했거나 연결 근거가 부족함. 읽지 않은 곳을 이상 없음으로 처리하지 않는다.
- `READY_FOR_TEST`: 전체 소스 범위를 읽었고 테스트 진입을 막는 확인된 결함이 없음. **런타임·모델 품질은 아직 미검증**이다. 잔여 실행 검증을 작고 구체적으로 지정한다.

ChatGPT가 리뷰 결과와 reviewedCommitSha, read-manifest hash, 남은 테스트 범위를 저장소 밖의 리뷰 보고서에 기록한다. Codex가 이 문서를 스스로 PASS로 채워 테스트를 시작할 수 없다. 별도 서명 서버·자동 승인 모델은 만들지 않는다. 다음 대화에서 ChatGPT의 실제 리뷰 결과를 읽고 SHA를 확인하면 된다.

테스트가 사용할 source/prompt/schema/runner가 리뷰 뒤 바뀌었으면 해당 커밋으로 다시 리뷰를 마친다. 보고서만 저장소 밖에 추가하는 것은 제품 소스를 바꾼 것이 아니다. 실행 직전 remote/local SHA를 확인한다. 테스트 결과를 좋게 만들려고 잠긴 source나 기대값을 바꾸지 않는다.

## 4. 리뷰 보고서 최소 형식

reviewStatus / repository / branch / reviewedCommitSha / reviewedAt / readManifest / findings(기능, 실제 코드, 사용자 영향, 관련 소비자, 필요한 수정) / unreviewed / runtimeUnknowns / nextTestScope. 이 필드들은 리뷰 증거용이며 제품 모델 입출력에 추가하지 않는다.
