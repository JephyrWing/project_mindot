# Codex: 전체 기능 흐름 결함 수정 및 재리뷰 제출

프로젝트는 JephyrWing/project_mindot, 대상 원격 브랜치는 fix/CBTAI다. 검토 기준 커밋은 085fe587afa7365e513c241073849cb69bcbe280다. 현재 F5 목록 응답과 F6 CBT_COMMAND DB 호환 수정을 진행 중이라면 그 작업 위에 통합한다. 로컬 변경이나 동료 커밋을 덮어쓰거나 기준 커밋으로 강제 되돌리지 않는다. 과거 대화나 이전 미전달 지시가 적용됐다고 가정하지 말고 동봉 리뷰와 현재 소스를 함께 읽는다.

목표는 기능 흐름 복구다. 사용자의 최우선 요구는 맥락에 맞는 CBT 질문이다. Agent/Writer/Assessor/같은 Agent의 후보 검토 구조, 원문 메모리, 의미 판단 권한을 유지한다. BEFORE는 처음 자동적 생각이고 AFTER는 그 판단의 잘못을 알아차리고 수정한 사용자의 생각을 AI가 정리한 값이다. 사용자 승인 없이 AFTER·유형을 확정하지 않는다. 중단은 OPEN으로 이어하고 완전 종료는 CANCELLED다.

현재 단계는 수정 후 원격 푸시와 ChatGPT 재리뷰다. 테스트, 서버를 띄운 실행 확인, canary, 유료 API 평가는 재리뷰 뒤 별도 단계에서 진행한다. 빌드·컴파일 등 기존 허용된 정적 확인과 기존 DB의 읽기 전용 카탈로그 조회는 할 수 있다. 체크를 통과시키려고 기대값이나 봉인 자료를 바꾸지 않는다.

## 먼저 이어서 처리할 기존 두 항목

- F5: 서버 Page 객체와 EmotionHistory/DailyCare 소비를 맞춘다. 서버 기본 5개만 전체 기록으로 취급하지 않는다. 필터/정렬/0-based 페이지/totalPages를 연결하고 최근 7일은 달력상 이번 주와 구분한다. 늦은 검색 응답과 마지막 페이지 삭제 후 빈 페이지도 다룬다.
- F6: 085fe58의 DB 제약 보완을 보존한다. 실제 기존 DB에서 operation CHECK 외에 reflection status, nullable payload/deadline 컬럼, UNIQUE/FK를 읽기 전용으로 대조하고 확인한 정의를 제출한다. 기존 데이터/허용값을 보존한다. 기존 CHECK가 없거나 이름이 다른 경우를 기존 파일만 보고 적용 성공으로 간주하지 않는다. DB 초기화, 마이그레이션 프레임워크 도입, 과거 원문 일괄 변환은 하지 않는다.

## 추가 수정

### F7: 늦은 감정 재분석 결과가 사용자 확정을 덮어씀

구조화 시작을 기록 단위로 직렬화하고 실행 중인 작업을 재사용한다. 완료도 같은 기록을 잠근 뒤 현재 유효한 STRUCTURE 작업이며 아직 반영 가능한 상태인지 확인한다. 실패·만료·교체된 작업의 늦은 결과와 COMPLETE 기록에는 반영하지 않는다. 구조화 완료 저장 실패도 별도 실패 처리로 남겨 PROCESSING에 방치하지 않는다.

수정이 이어져야 하는 경계: A/B 완료 순서가 바뀌는 경우, 확정 직후 늦은 결과, 재분석 중 삭제, 실행 만료 후 재시도를 함께 확인한다. 확정 데이터·CBT snapshot·리포트가 과거 AI 값으로 회귀하지 않아야 한다.

### F8: 원문은 저장됐는데 실패로 안내하고 재시도 시 새 기록을 만듦

원문 저장 성공과 AI 구조화 성공을 응답과 화면에서 구분하고, 저장된 ID와 구조화 실패 상태를 돌려준다. 최초 논리 저장의 client key·원문·발생 시각을 재전달에도 유지하며, 서버가 같은 사용자의 같은 요청을 원문 행 생성 전에 찾도록 한다. 기존 AiJobs와 짧은 기록/사용자 잠금을 활용할 수 있다. 내용이 같은 별개 기록을 원문 해시만으로 합치지 않는다.

수정이 이어져야 하는 경계: AI 실패, 원문 저장 후 응답 유실, 같은 요청 재전송, 같은 문장을 나중에 별도 기록하는 경우를 구분한다. 저장된 ID 반환만 고치고 응답 유실 중복을 남기지 않는다.

### F9: CBT 진입 경로마다 자동적 생각의 허용 형식이 다름

상세와 CBT 진입의 필수 입력 검사를 일치시키고 한국어 종결·어절 정규식을 제거한다. 공백 및 필요한 전송 길이 검사는 유지한다. 문장의 CBT 관련 의미는 기존 Agent가 다루며 별도 문법 판정 모델을 추가하지 않는다.

수정이 이어져야 하는 경계: 짧은 생각·질문형 생각·영어·일반 한국어가 어느 진입점에서도 일관되게 처리되고 빈 입력은 여전히 차단되는지 확인한다.

### F10: 지난주 기록으로 이번 주에 완료한 CBT만 있으면 주간 리포트가 막힘

주간 감정 기록과 완료 CBT가 모두 없을 때만 빈 기간으로 처리한다. 감정 기록이 0개여도 완료 CBT를 표시하고 감정 평균은 기록 없음으로 둔다. 서로 다른 날짜 기준은 명시하며 과거 성찰을 새 AFTER로 재분류하지 않는다.

수정이 이어져야 하는 경계: 감정 기록만 있는 주, CBT만 완료한 주, 둘 다 있는 주, 둘 다 없는 주를 대조한다. PDF는 현재 감정 발생일 기준으로 연결 CBT를 찾으므로, 이 날짜 의미를 화면에 드러내거나 별도 조회 기준을 명확히 정한 뒤 연결한다. PDF 날짜 기준까지 묵시적으로 바꿨다고 가정하지 않는다.

### F11: 유사한 과거 사례 검색에 현재 기록 자신이 포함됨

현재 recordId를 검색 요청에 전달하고 두 검색 SQL 모두에서 자기 기록을 LIMIT 전에 제외한다. 새 형식에서 유형을 모두 거부한 사용자 확인 AFTER의 검색 자격은 유지한다.

수정이 이어져야 하는 경계: 현재 사례+다른 사례 하나의 같은 유형을 과거 두 사례로 세지 않아야 한다. 제외 후 topK를 다른 사례로 채우고, 자기 사례만 남는 경우 검색 근거 없음으로 처리한다. 날짜·횟수 자격과 반환 사례 수가 서로 맞는지도 확인한다.

### F12: 감정 발생 시각을 고치면 검색 벡터가 이전 시간대로 남음

임베딩 입력이 실제로 달라지는 수정에서 해당 벡터를 갱신 대상으로 표시하거나 무효화하고 기존 비동기 임베딩 경로로 재생성한다. 같은 시간대 안의 시각 이동처럼 입력이 같으면 불필요하게 생성하지 않는다. 변경 이전 입력으로 실행 중이던 임베딩의 늦은 저장도 막는다.

수정이 이어져야 하는 경계: 갱신 실패 후 재시도, 시각 수정과 임베딩 완료의 교차, 같은 입력으로의 단순 날짜 이동을 구분한다. AFTER·유형 승인과 대화 원문은 바뀌지 않아야 한다.

### F13: 허용된 긴 대화·이모지가 PDF에서 누락 또는 생성 실패를 일으킴

대화 블록을 페이지별 줄 단위로 분할하고 화자·이어짐을 표시한다. 문자 처리는 Unicode code point 단위로 하며 지원 폰트 fallback 또는 명시적인 대체 표시를 제공한다. DB 원문을 고치거나 조용히 글자를 삭제하지 않는다. 같은 표 작성 방식의 긴 정보 행도 함께 점검한다.

수정이 이어져야 하는 경계: 60줄 답변의 처음·중간·마지막이 모두 보여야 한다. 한국어/영어/이모지가 섞인 원문, BEFORE·AFTER, 전체 대화에서 생성 실패 없이 보존 또는 명시적 대체되는지 확인한다. 실제 PDF 렌더링 확인은 후속 테스트 단계에서 수행한다.

### F14: 10점 감정 강도가 주간 리포트와 마음 돌봄에서 5점 척도로 표시됨

감정 강도의 표시를 0~10으로 통일하고 도움 정도의 0~5와 구별한다. 표시를 맞추려고 저장값을 나누거나 기존 데이터를 다시 쓰지 않는다. DailyCare의 활동 선택 임계값 4는 별도 제품 규칙이므로 근거 없이 8로 바꾸지 않는다.

수정이 이어져야 하는 경계: 0/4/8/10 및 미입력 값을 상세·목록·리포트·마음 돌봄·PDF에서 대조한다. 도움 점수 /5는 그대로 유지한다.

## 수정 후 스스로 대조할 사항

검증 절차를 늘리는 것이 목적이 아니다. 현재 결함을 만든 실제 경계만 대조한다. 모델 출력을 대역으로 직접 주입한 테스트를 모델 질문 품질의 증거로 쓰지 않는다.

- 사용자 원문 저장과 AI 분석의 실패를 구분한 뒤, 네트워크 재전송이 새 감정 기록이나 새 답변을 만들지 않는지 확인한다.
- 기록·성찰의 상태를 고친 뒤, 뒤늦은 AI 결과/임베딩이 최신 확정 상태를 덮어쓰는 경로가 없는지 소스로 추적한다.
- 목록을 Page로 고친 뒤 해당 함수를 쓰는 모든 화면의 범위·단위·검색·페이지 소비를 확인한다.
- CBT만 있는 주의 리포트를 허용한 뒤, 빈 감정 평균을 0으로 위조하거나 도움 점수와 척도를 혼동하지 않는다.
- 검색 자기 사례 제외는 LIMIT 전에 적용하고, 유형 전부 거부 AFTER 및 구형 확정 사례 자격을 훼손하지 않는다.
- PDF 입력 원문을 삭제/축약해서 장문·이모지 문제를 숨기지 않는다.

신규 큐·별도 워크플로 서버·의미 검증 모델·상태 장부를 추가할 필요는 없다. 기존 구조 안에서 호출 계약, 짧은 저장 경계, 실제 소비자를 고친다. F7/F8의 원문 저장 경계는 CBT의 의미 프롬프트를 수정할 이유가 아니다.
